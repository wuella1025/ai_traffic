前往實作測試區

核心 AI 辨識能力

結合深度學習物件定位與傳統電腦視覺像素統計

斑馬線物件偵測

搭載輕量化 YOLO26n 單類別模型，透過 Letterbox 等比例前處理與非極大值抑制（NMS），精準框選影像中的斑馬線區域。

標線像素對比與能見度分析

直接回溯原始解析度影像裁切偵測框，轉換為標準灰階後計算百分位對比差（P90−P10）與平均亮度，量化褪色、磨損及過暗/過曝狀態。

幾何位置與視野評估

針對駕駛前向視角，計算標線邊界貼邊程度、畫面底端視線盲區距離與垂直高度佔比，評估道路標線於視野中的完整性與壓迫感。

自動化風險分級報告

彙整 5 項客觀量化指標（總分 0~7 分），自動判定低、中、高風險等級，並列舉具體的數值明細與硬體改善檢核建議。

畫面標註圖例： 綠色邊界框（#00FF00）：模型偵測到的斑馬線（crosswalk）範圍 crosswalk 88.5%：標籤右側百分比代表模型对该區域為斑馬線的信心程度（僅供參考，不計入風險扣分）

靜態危險度評估標準

系統取信心度最高的一條斑馬線進行原圖像素與幾何分析（總分 0~7 分，分數越高代表硬體或視角條件越差）

類別 評估指標 計算方式 評分規則（暫定門檻）
A. 標線狀態
主要指標		 1. 標線清晰度
(0~2 分)		 框內灰階像素之「第 90 百分位 − 第 10 百分位」，衡量白線與柏油路面的對比度 ≥ 80 → 0 分
50 ~ 80 → 1 分
< 50 → 2 分（嚴重褪色/磨損）
2. 框內能見度
(0~2 分)		 框內所有像素之平均灰階值（$0.299R+0.587G+0.114B$），評估環境光照條件 70 ~ 200 → 0 分
40~70 或 200~230 → 1 分
< 40 或 > 230 → 2 分（過暗/過曝）
3. 完整度
(0~1 分)		 偵測框任一側與影像邊緣距離小於影像寬或高的 2% 未貼邊 → 0 分
任一側 < 2% → 1 分（可能裁切或遮擋）
B. 位置與大小
限駕駛視角		 4. 視線盲區
(0~1 分)		 底邊距離比 = $(\text{圖高} - (y + h)) / \text{圖高}$ ≥ 0.18 → 0 分
< 0.18 → 1 分（過於貼近車頭盲區）
5. 空間壓迫
(0~1 分)		 高度佔比 = $h / \text{圖高}$ ≤ 0.25 → 0 分
> 0.25 → 1 分（標線佔據過大垂直視野）
風險分級判定標準
  • 0 ~ 1 分低風險 狀態與視角良好
  • 2 ~ 3 分中風險 部分指標異常需留意
  • 4 ~ 7 分高風險 多項標線或視角缺陷
  • 無目標無法評估 未偵測到斑馬線
參數說明：上述所有門檻數值均為教學與系統示範用暫定值，使用者可直接於網頁原始碼 <script> 最上方修改常數進行校正。

交通風險與辨識場景

系統針對各類靜態道路影像情境之偵測方式與判定結果

風險類別 辨識場景描述 偵測方式與系統評估結果
標線褪色或磨損 長期車輛輾壓導致白漆剝落、灰黑化，與柏油路面色差不明顯。 ROI 灰階之 P90 − P10 對比差低於 80（甚至低於 50），「標線清晰度」計入 1~2 分並提示重繪標線。
光線過暗或過曝 夜間無路燈、樹蔭遮蔽導致畫面昏暗，或逆光/強光反射造成死白。 框內平均灰階落於 <70 或 >200 區間，「框內能見度」計入 1~2 分，提示光線條件影響辨識度。
斑馬線被切掉或遮住 鏡頭拍攝角度偏斜，或標線邊緣緊貼畫面四周邊界。 偵測框任一側距影像邊緣小於 2%，「完整度」計入 1 分，提示畫面可能未完整涵蓋穿越道全貌。
視線盲區 行車記錄器視角中，斑馬線過於靠近畫面最下緣（車頭前方死角）。 底邊距離比例小於 0.18，「視線盲區」計入 1 分，提示標線位於駕駛近距離盲區範圍。
空間壓迫 距離斑馬線極近或廣角變形，導致標線在垂直方向佔據過大比例。 偵測框高度佔全圖高度比例大於 0.25，「空間壓迫」計入 1 分，提示近距離視覺壓迫感較高。
未偵測到斑馬線 畫面中無斑馬線、標線已完全磨滅，或嚴重遮擋導致信心度低於 0.4。 模型無輸出有效框，狀態顯示 0 條，評估報告顯示「無法評估（灰色標籤）」。
目前尚未支援之項目：本系統專注於單張靜態照片之「斑馬線硬體與幾何狀態」分析，目前不支援紅綠燈號誌辨識、行人/騎士偵測、安全帽偵測，亦不包含未禮讓行人、違規停車或逆向行駛等動態交通違規行為判定。

教學與架構延伸

從資料標註到純前端邊緣推論的完整開發管線

STEP 1 · 資料準備
Roboflow 標註與前處理

收集街景影像並標註單一類別 crosswalk，統一輸出為 640×640 規格與 YOLO 格式資料集。

STEP 2 · 模型訓練
Google Colab 訓練

於雲端 GPU 環境使用 Ultralytics 框架訓練輕量化 YOLO26n 模型，收斂後取得最佳權重檔。

STEP 3 · 格式轉換
匯出 ONNX 模型

將模型匯出為跨平台標準 best.onnx（無內建 NMS，輸出張量 [1, 5, 8400]），部署至 GitHub Pages。

STEP 4 · 前端推論
瀏覽器即時分析

透過 ONNX Runtime Web 載入模型執行推論，並可隨時調整 <script> 最上方的門檻常數以微調評估靈敏度。

純地端推論（Zero-Backend）

所有影像前處理、神經網路推論與像素運算皆在使用者瀏覽器（WebAssembly）中完成，照片不上傳雲端，兼顧隱私與零伺服器維運成本。

YOLO 空間標定與 Letterbox 還原

實作等比例灰邊填充（RGB 114）避免標線長寬比失真，並精確反算縮放倍率與位移量，將偵測框無損映射回原始高解析度圖片座標。

像素分析與評分決策引擎

結合深度學習定位與可解釋的統計規則引擎（灰階百分位差、空間比例幾何），避免純黑箱判斷，提供可量化校正的診斷依據。

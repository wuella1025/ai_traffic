01 // CORE CAPABILITIES

核心 AI 辨識能力

結合輕量化深度學習物件偵測與原圖像素幾何分析

斑馬線物件偵測

載入 YOLO26n 單類別模型，透過 Letterbox 等比例補邊與非極大值抑制（NMS），精準定位影像中的斑馬線區域。

標線像素對比與能見度分析

回溯原始未縮放影像裁切偵測框，轉換灰階後計算百分位對比差（$P_{90} - P_{10}$）與平均亮度，量化褪色、磨損及過暗/過曝狀態。

幾何位置與視野評估

針對駕駛前向視角，計算邊界貼邊完整度、畫面底端視線盲區比例與垂直高度佔比，評估標線於視野中的空間分佈。

自動化風險分級報告

彙整 5 項客觀指標（總分 0~7 分），自動判定低、中、高風險等級，並列舉實際量測數值明細與硬體改善建議。

畫面標註圖例： 綠色框線（#00FF00）：代表偵測到的斑馬線（crosswalk） crosswalk 89.5%：百分比代表模型信心程度（僅供參考，不計入風險分數）
02 // ASSESSMENT CRITERIA

靜態危險度評估標準

取信心度最高的一條斑馬線回溯原圖進行計算（門檻皆為教學示範用暫定值）

指標分類 評估項目 原圖計算公式 評分規則（暫定門檻）
A. 標線狀態
主要指標 		1. 標線清晰度
(0 ~ 2 分)		 框內灰階百分位對比差：
$$\Delta G = P_{90} - P_{10}$$
衡量白線與路面反差
 $\Delta G \ge 80$ → 0 分
$50 \le \Delta G < 80$ → 1 分
$\Delta G < 50$ → 2 分（褪色/磨損）
2. 框內能見度
(0 ~ 2 分)		 框內像素平均灰階值：
$$G = 0.299R + 0.587G + 0.114B$$
反映現場光照與曝光狀態
 $70 \le \bar{G} \le 200$ → 0 分
$40 \sim 70$ 或 $200 \sim 230$ → 1 分
$\bar{G} < 40$ 或 $\bar{G} > 230$ → 2 分
3. 完整度
(0 ~ 1 分)		 邊界貼邊距離檢核：
$$d_{\text{edge}} < 0.02 \times \text{影像對應邊長}$$
 四邊皆未貼邊 → 0 分
任一側 $< 2\%$ → 1 分（裁切/遮擋）
B. 位置與大小
限駕駛視角 		4. 視線盲區
(0 ~ 1 分)		 底邊距離比例：
$$R_{\text{blind}} = \dfrac{H - (y + h)}{H}$$
 $R_{\text{blind}} \ge 0.18$ → 0 分
$R_{\text{blind}} < 0.18$ → 1 分（車頭盲區）
5. 空間壓迫
(0 ~ 1 分)		 框高度佔全圖比例：
$$R_{\text{press}} = \dfrac{h}{H}$$
 $R_{\text{press}} \le 0.25$ → 0 分
$R_{\text{press}} > 0.25$ → 1 分（視野壓迫）
左右滑動可檢視完整表格
總分分級方式 (0~7 分)
低風險（綠色標籤） 0 ~ 1 分
中風險（橘色標籤） 2 ~ 3 分
高風險（紅色標籤） 4 分以上
無法評估（灰色標籤） 未偵測到斑馬線
門檻可調整：上述門檻數值均為暫定示範值，可直接修改網頁原始碼 <script> 最上方的常數進行校正。
03 // SCENARIO MATRIX

交通風險與辨識場景

針對單張靜態道路影像之各類標線與視角情境判定方式

風險類別 辨識場景 偵測方式與結果
標線褪色或磨損 白漆剝落、輪胎輾壓痕跡深重，導致白色標線與路面灰階接近。 ROI 灰階 $\Delta G = P_{90} - P_{10}$ 低於 80（或低於 50），「標線清晰度」計 1~2 分並建議評估補繪標線。
光線過暗或過曝 夜間照明不足、陰影遮蔽，或強烈逆光造成路面反白。 框內平均灰階 $\bar{G} < 70$ 或 $\bar{G} > 200$，「框內能見度」計 1~2 分並提示光照條件異常。
斑馬線被切掉或遮住 鏡頭拍攝角度偏斜，或標線邊界緊貼影像上下左右四邊。 偵測框任一側距邊界小於影像尺寸 2%，「完整度」計 1 分，提示標線範圍未完整入鏡。
視線盲區 行車記錄器前向視角中，斑馬線過於貼近畫面最下緣（車頭前方死角）。 底邊距離比例 $R_{\text{blind}} < 0.18$，「視線盲區」計 1 分，提示已進入近距離駕駛視野盲區。
空間壓迫 車輛距離穿越道極近，使標線在垂直方向佔據畫面超過四分之一高度。 偵測框高度佔比 $R_{\text{press}} > 0.25$，「空間壓迫」計 1 分，提示近距離空間壓迫感較高。
未偵測到斑馬線 影像中無行人穿越道、標線完全磨滅，或嚴重遮擋導致信心低於 0.4。 偵測數量為 0，報告顯示「無法評估（灰色標籤）」，不進行硬體評分。
左右滑動可檢視完整表格
目前尚未支援：本系統專注於單張靜態照片的「斑馬線硬體狀態」分析，目前尚未支援紅綠燈號誌辨識、行人與騎士偵測、安全帽偵測，亦不包含未禮讓行人、違規停車或逆向行駛等動態交通行為判定。
04 // ARCHITECTURE & FEATURES

教學與架構延伸

從資料集標註、模型訓練到瀏覽器端即時推論的完整流程

STEP 1 · Roboflow
資料標註與前處理

收集街景照片並標註單一類別 crosswalk，統一輸出為 640×640 規格資料集。

STEP 2 · Colab
YOLO26n 模型訓練

於 Google Colab GPU 環境訓練輕量化單類別偵測模型，取得收斂後之最佳權重。

STEP 3 · ONNX
模型轉檔與靜態部署

匯出無內建 NMS 之 best.onnx（輸出 [1,5,8400]），與網頁一同部署至 GitHub Pages。

STEP 4 · Frontend
前端推論與門檻校正

瀏覽器內直接執行推論與原圖灰階分析，可隨時修改 <script> 最上方的門檻常數。

系統核心技術特色

純地端推論（Zero-Backend）

透過 ONNX Runtime Web（WebAssembly）在用戶端瀏覽器直接執行推論，照片無須上傳雲端伺服器，兼顧隱私與零維運成本。

YOLO 空間標定與無損還原

實作等比例灰邊填充（RGB 114）之 Letterbox 縮放避免標線變形，並反算縮放倍率與位移量，將偵測框精準還原至原圖座標。

像素分析與評分決策引擎

結合深度學習定位與白箱統計規則（灰階百分位差、空間比例幾何），輸出可追溯的量測數值與硬體評估依據。
